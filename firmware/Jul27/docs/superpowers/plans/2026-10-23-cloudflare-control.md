# Cloudflare hosted BlindBalance control implementation plan

> For agentic workers: use superpowers:subagent-driven-development. Preserve existing unrelated and uncommitted work. No deployment or firmware flashing is implied by passing local tests.

**Goal:** Replace ESP32-hosted control pages with the existing B.R.P site and a managed Cloudflare backend, avoiding a manually reactivated idle Supabase project.

**Architecture:** Netlify serves `/control/`. An HTTPS Cloudflare Worker uses D1 for authorized device/pair status and commands, and private R2 for finalized captures. ESP32s exchange status/commands through an independent worker; control execution and ESP-NOW feedback remain local.

**Tech stack:** dependency-light JavaScript/HTML/CSS, Worker Web APIs, D1 SQL, R2, ESP32 Arduino/FreeRTOS with bundled cJSON/mbedTLS. Node built-in tests and SQLite for backend integration tests.

**Spec:** `../specs/2026-10-23-hosted-blindbalance-control-design.md`, with the provider/auth changes below superseding Supabase details.

## Shared HTTP contract v1

All API requests use `Authorization: Bearer <opaque key>`; authenticated backend selects device or operator identity from its token hash, never trusts a client-selected pair. Paths are below the configured HTTPS API base. JSON responses include an `error` string for failures; no secrets are logged. CORS allows only configured exact site/preview origins, supports OPTIONS and exposes download headers. Responses are no-store.

Device `POST /v1/device/exchange` body:
```
{bootId:"uint32-as-string", sequence:1, status:{arm:"L",motorEnabled:true,
 feedbackDeadZone:0.055,settingsRevision:0,peerFresh:true,tempC:25,
 rawLogging:false,rawLogBytes:0,captureId:"",captureUploaded:false,
 recalibrating:false,...existingDiagnostics},
 ack:null | {id:"uuid",revision:1,result:"applied"|"failed",message:"..."}}
```
Response: `{serverTimeMs, commands:[{id,revision,action,target,bootId,ttlMs,value?,captureId?}]}`. Send at most one command per exchange. Worker keeps at most one HTTP exchange in flight; sequences increase per boot. Expiry TTL must be reduced by request elapsed time on device. Firmware retransmits acknowledgments until a successful exchange. Backend accepts idempotent results but refuses unknown/wrong-boot/wrong-scope acknowledgments. It must not mark rejected stale-sequence exchanges fresh.

Operator `GET /v1/operator/state` returns `{pairId,revision,serverTimeMs,devices:[{id,arm,bootId,lastSeenMs,status}],commands:[{id,revision,action,target,value?,captureId?,createdMs,expiresMs,state,results:{L?,R?}}],captures:[{deviceId,captureId,bytes,sha256,createdMs}]}`. Limit recent command history and captures. `state` is pending/applied/failed/expired/unknown; results per required arm expose whether actually applied. For shared settings, left acknowledges execution and right confirms the same settingsRevision in a fresh status with the captured right boot. HTTP acceptance alone is never applied.

Operator `POST /v1/operator/commands`: `{expectedRevision,action,target,value?,captureId?}` returns `{id,revision}` or 409 stale revision/busy, 400 invalid args, 503 offline. Actions: `set_motor_enabled` (boolean, target `pair`), `set_sensitivity` (number, target `pair`), `raw_start`, `raw_stop`, `raw_clear`, `recalibrate` (target `L` or `R`). `raw_start` requires no existing capture; backend assigns captureId equal to command UUID. stop/clear target the exact current captureId. One unresolved command per pair; expire old commands before admitting another. Compare-and-set + insertion must be atomic. Capture both boots when accepting shared settings. Device transport delivers shared commands only to left, per-board commands only to their target. A boot change invalidates that boot's pending commands.

Device `PUT /v1/device/captures/<captureId>` streams finalized CSV (max 2,000,160 bytes); `X-Content-SHA256` lowercase SHA-256, `Content-Length` exact. Require an authorized issued raw_start capture ID for this device, stopped status with matching capture ID/bytes, and validate size/hash before downloadable metadata. Response `{captureId,bytes,sha256}`. Same ID/hash re-upload is idempotent; conflicting content rejected. Firmware marks uploaded only after matching response. Retain local capture until explicit clear. Operator `GET /v1/operator/captures/<deviceId>/<captureId>` returns authorized CSV. Never expose a public R2 URL.

## Review focus

1. Duplicate/expired/reordered commands cannot flip twice, restart capture or erase the wrong file: backend and pure firmware command tests.
2. Unauthorized/wrong-pair identities cannot control devices or download logs: real SQL worker API tests.
3. A delayed exchange, reboot or partial pair application cannot show false success: sequence/boot tests and UI derived-state tests.
4. TLS/network/flash operations cannot move into the sensing loop or race capture: firmware ownership review, compile and physical timing checklist.
5. Existing site routes/assets and generated deployment do not expose private config: build allowlist and route/browser checks.
